# External Integrations
_Generated: 2026-04-12_

## Summary

MechanicalDesignTools integrates with a local PostgreSQL database (accessed via an MCP server for AI assistant tooling), a Context7 documentation API (also MCP-only, for AI assistant use), and the Genesis physics simulator (GPU-based, Docker-isolated in the Robot_Simulations/eden sub-project). There are no external SaaS APIs, no authentication providers, and no webhooks. The core `engineering_tools` application runs fully offline using only local files and the installed Python packages.

## MCP Servers (AI Assistant Tooling — Not Application Code)

These integrations are configured in `.mcp.json` and are consumed by the Claude AI assistant, **not** by the engineering application itself.

**Context7 Documentation API:**
- Purpose: Fetches current library documentation for the AI assistant during development
- Provider: Upstash Context7 (`@upstash/context7-mcp`)
- Transport: `npx -y @upstash/context7-mcp` (Node.js process, not Python)
- Auth: API key stored in `.mcp.json` as `CONTEXT7_API_KEY`
- Used by: Claude AI assistant only

**PostgreSQL via MCP:**
- Purpose: Allows the AI assistant to query the engineering data database
- Transport: `npx -y @modelcontextprotocol/server-postgres`
- Connection: `postgresql://admin:***@localhost:5432/engineering_data`
- Host: `localhost:5432` (local dev database)
- Data directory: `.dev_tools/postgres_data/` (PostgreSQL 15 data files committed to repo)
- Used by: Claude AI assistant only; no application code imports psycopg2/SQLAlchemy

## Databases

**PostgreSQL 15 (local dev):**
- Version: 15 (confirmed by `.dev_tools/postgres_data/PG_VERSION`)

## Physics Simulators

**Genesis (`genesis-world`):**
- Purpose: GPU-accelerated multi-physics simulation for robot reinforcement learning
- Sub-project: `Robot_Simulations/eden/`
- Backends supported: CUDA (primary), Vulkan, Metal, CPU
- Integration point: `Robot_Simulations/eden/experiments/hello_genesis.py`, `Robot_Simulations/eden/eden/core/` (Phase 2 implementation planned)
- CAD assets fed in: STEP/STP files from `Robot_Simulations/eden/cad_source/`; robot URDF/MJCF (e.g., Franka Emika Panda `xml/franka_emika_panda/panda.xml`) loaded at runtime from Genesis's bundled assets
- Docker image: `Robot_Simulations/eden/docker/Dockerfile.training` — FROM `pytorch/pytorch:2.1.0-cuda12.1-cudnn8-runtime`
- Requires: NVIDIA GPU, CUDA 12.1, Docker with `nvidia-container-toolkit`

## Engineering Standards Data (Embedded, Not External)

These are local data files bundled with the project, not network services.

**AISC Shapes Database:**
- File: `engineering_tools/mech_core/standards/materials/data/aisc_shapes.json`
- Content: Complete AISC v16.0 steel section properties (W, C, HSS, L shapes, metric)
- Access: `engineering_tools/mech_core/components/members/aisc.py` — `get_section()`, `get_shapes_by_type()`

**Standard Plate Thicknesses:**
- File: `engineering_tools/mech_core/standards/materials/data/standard_thicknesses.json`

**NC1 / DSTV CNC Files:**

- Sample input: `engineering_tools/projects/PCR41_test/sample_beam.nc1`
